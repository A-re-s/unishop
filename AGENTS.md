# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, Cursor, etc.) when working with code in this repository.

## Project

Unishop — a university classifieds board (students post/search listings for textbooks, electronics, furniture, etc., favorite them, and contact the seller via Telegram). Backend: FastAPI + SQLAlchemy 2.0 (async). Frontend: React 19 + TypeScript (Feature-Sliced Design). See `README.md` for product features, full setup instructions, and deployment notes — this file focuses on what agents need to build, test, and navigate the codebase.

## Commands

All commands are exposed through `just` (`just --list` for the full list). The whole stack runs in Docker Compose (`just up`); there's normally no need to run backend/frontend outside containers.

**Lint & format**
```bash
just lint-backend / just lint-backend-fix     # Ruff
just lint-frontend / just lint-frontend-fix    # Biome
just format-backend / just format-frontend
just lint / just format                        # both stacks
```

**Tests**
```bash
just test-backend                              # cd backend && uv run pytest
just test-frontend                             # cd frontend && npm run test (vitest run)
just test                                      # both

# Single test:
cd backend && uv run pytest tests/test_health.py::test_name
cd frontend && npx vitest run src/path/to/file.test.tsx
```

**Database (Alembic)**
```bash
just makemigrations "message"   # autogenerate from model changes
just migrate / just migrate-down            # dev stack
just migrate-prod / just migrate-down-prod  # prod stack (Postgres not reachable from host there)
```

**Docker / dev stack**
```bash
just up / just down / just restart
just logs-backend / just logs-frontend
just seed    # python3 scripts/seed.py — fills dev DB with demo users/listings (requires `just up`)
```

**Commits & versioning** — Conventional Commits, enforced on the PR title (PRs are squash-merged), checked by CI. Version bumps go through Commitizen and touch `backend/pyproject.toml`, `frontend/package.json`, and `CHANGELOG.md` together:
```bash
just bump-preview     # preview next version/changelog, no changes
cz bump --changelog   # actually bump
```

## Architecture

### Backend (`backend/src/backend/`)

Layered: `api/routers` (FastAPI endpoints) → `services` (business logic) → `repositories` (data access) → `db/models` (SQLAlchemy models). Routers depend on services via FastAPI `Depends`; services receive a `UnitOfWork` rather than a raw session.

- **Unit of Work** (`db/uow.py`): `UnitOfWork` opens one `AsyncSession` per request and exposes all repositories (`users`, `categories`, `listings`, `favorites`, `listing_photos`) as attributes on itself, so a service can touch multiple repositories against the same transaction and commit/rollback once. Obtained per-request via the `get_uow` dependency in `api/dependencies/db.py`.
- **Auth** (`core/security/`, `api/routers/auth.py`): Login is Keycloak OIDC (Authorization Code Flow) via Authlib. `SessionMiddleware` in `main.py` is used *only* by Authlib to hold OAuth state/nonce/PKCE between `/login` and `/callback` — it is unrelated to the app's own session. The app's real session is a random token stored in Redis (`core/security/sessions.py`), mapping to `{user_id, id_token}`; the Keycloak `id_token` is kept so logout can pass it back as `id_token_hint`, letting Keycloak end the browser's SSO session too (otherwise the next login would silently skip the credentials form). `api/dependencies/auth.py::get_current_user` reads the session cookie, resolves it through Redis, then loads the `User` via the UoW — this is the dependency routers use to require authentication.
- **Storage** (`core/storage.py`, `services/photo_service.py`, `services/avatar_service.py`): listing photos and avatars are stored in MinIO (S3-compatible) via `aioboto3`; the DB only stores object keys/URLs.
- **Listing status machine**: active → (booked | sold), booked → (active | sold), sold is final. Enforced in `services/listing_service.py`; only the listing's author may change it.
- **Migrations**: Alembic env lives at `db/migrations/`; models are the source of truth, migrations are autogenerated from them (`just makemigrations`) and never hand-written from scratch.
- **Locale detection**: `api/routers/locale.py` / `services/locale_service.py` implements `GET /v1/locale/detect`, used by the frontend as one step of its language-resolution chain (see below) — it geolocates by request IP.

### Frontend (`frontend/src/`)

Feature-Sliced Design: `app/` (composition root: router, Redux store, global styles) → `pages/` → `widgets/` → `features/` → `entities/` → `shared/`. Each higher layer may only import from layers below it.

- **State/data**: Redux Toolkit + RTK Query. `shared/api/base-api.ts` defines the single RTK Query base API instance that entity/feature-level API slices inject endpoints into, rather than each slice creating its own client.
- **Reusable listing feed**: `widgets/listing-feed` implements search-by-title, category/status filters, price/date sorting, and pagination as one component reused across the Home, Favorites, and "My listings" pages — don't duplicate this logic per page.
- **i18n** (`react-i18next`, `shared/locales/*.json`, 13 languages): on first visit the language is resolved in order — saved choice in `localStorage` → browser `Accept-Language` header → IP geolocation via the backend's `GET /v1/locale/detect` → default `en`. The result is cached in `localStorage` so the resolution chain only runs once. Manually changing the language in profile settings also writes to `localStorage` and overrides auto-detection. `ar`/`ur` switch the layout to RTL automatically.
- **Testing**: Vitest + Testing Library, `src/test-setup.ts` is the global test setup referenced from `vite.config.ts`.

### Cross-cutting

- `docker-compose.yml` (dev) vs `docker-compose.prod.yml` (prod, adds nginx as the single entrypoint and drops bind-mounts/hot-reload) — see README's "Продакшн" section before changing either.
- Env files are per-app (`.env`, `backend/.env`, `frontend/.env`), each with a committed `.env.example`; only the `.example` files are tracked by git.
- `keycloak/realm-import.json` is the realm config Keycloak boots from in dev; changes to clients/roles/redirect URIs for local dev go there.
